## 5. Assistant 回复 DOM（已验证事实）

**已排除方案（不可靠，记录为 discard）：**

- `document.body.innerText`：含整个 ChatGPT UI + 历史消息，无法稳定界定当前 Assistant reply
- 动态 CSS class（如 `MarkdownRoot-rZKhxa`）：不能视为稳定 contract
- `[role="article"]` 作为唯一消息边界：不可靠

**已发现稳定语义属性（已验证事实）：**

- Assistant Markdown 正文锚点：
  ```css
  [data-markdown-text-style="assistant-message"]
  ```
  - 实测 `document.querySelectorAll('[data-markdown-text-style="assistant-message"]')` 能找到当前页面已有 Assistant 回复（当时 count=4）
- Assistant 消息级容器：Asssistant Markdown 节点向上 `closest('[data-chatgpt-selection-message-id]')` 可得消息级容器
  - 边界实验（已验证）：Markdown 节点自身 `textLength` 与 message-level container `textLength` 一致；更高层 `[data-content-search-unit-key]` 会比 Markdown 多出少量 UI 前缀文本（如「ChatGPT 说：」）
- message-id 候选（比动态 class 更适合作为消息身份标识）：
  - `[data-chatgpt-selection-message-id]`
  - `[data-chatgpt-selection-conversation-id]`
  - 更高层还发现：`[data-content-search-unit-key]`、`[data-chatgpt-search-unit-key]`、`[data-chatgpt-search-message-ids]`

**当前最佳 Assistant 正文候选（已验证事实，但保真度端到端取回待 P0-10/11）：**

```javascript
const nodes = document.querySelectorAll('[data-markdown-text-style="assistant-message"]');
// 取最后一个节点作为候选最新 Assistant reply
```

**假设/未验证**：上述 selector 在当前 Chrome/ChatGPT UI 版本之外的稳定性未验证，不得声称永久稳定。

## 7. ChatGPT 输入框（已验证事实）

- 当前 Composer 输入框**不是 textarea**，而是：

```html
<div role="textbox" contenteditable="true" aria-label="询问 ChatGPT" class="ProseMirror ...">
```

- 定位 selector（已验证事实）：

```css
[role="textbox"][contenteditable="true"]
```

- 注意：不能依赖 `editor.value`（ProseMirror `DIV`，无 `value` 属性）

## 8. 输入注入（已验证事实）

注入方式（已验证成功）：

```javascript
editor.focus();
document.execCommand("insertText", false, testText);
```

- 实测 `editor.innerText` 能出现测试文本（`TEST_INPUT_ONLY` / `TEST_SEND_DISCOVERY` 均成功）

**空状态判定（已验证事实）：**

- 清除测试文字后，空 ProseMirror 编辑器可能保留 `"\n"`（空段落，不代表残留测试内容）
- 正确判空应使用：`(editor.innerText || "").trim() === ""`，而非 `editor.innerText === ""`

## 9. 发送按钮 selector —— 修订（重要：此前结论已被推翻）

> **修订声明**：本证据包早期 §9 曾记录 `button[type="submit"][aria-label="发送"]` 为「PASS」。该结论**仅来自一次扫描（输入 `P0_SEND_BUTTON_RECON` 后全页面扫描 totalButtons=216 发现 index=211 的 submit 发送按钮）**。后续 **P0-08 真实发送探针再次检查时**：

```text

```

因此：

**结论（已验证事实）：「发送按钮 selector 已稳定确定」= NO。** 不能把 `button[type="submit"][aria-label="发送"]` 作为已确认的长期稳定 selector。

- **因此 `bg-composer-primary` 也不可作为发送按钮标识**（它出现在一个语音按钮上）

**合理假设（未验证）**：发送按钮属于 Composer 动态 UI，其 DOM 状态依赖输入内容与渲染时机；但**目前没有取得可稳定、可复现的发送按钮 selector 实测证据**。

## 10. Enter 发送实验（已验证事实：方案不可靠，discard）

已在 DOM 层面执行：

```javascript
editor.dispatchEvent(new KeyboardEvent("keydown", {
  key: "Enter", code: "Enter", keyCode: 13, which: 13,
  bubbles: true, cancelable: true
}));
```

实测结果：

```text
success = true
dispatched = false
defaultPrevented = true
assistantCount = 4 → 4
matchingUserContainers = 1   // 注意：非成功证据
```

解读（已验证事实）：

- DOM `KeyboardEvent` 可以被 dispatch；
- 但该事件被页面 `preventDefault` 阻止（`defaultPrevented=true`，`dispatched=false`）；
- **没有产生新的 Assistant 回复**（assistantCount 4→4 无变化）；
- `matchingUserContainers=1` **不能作为成功证据**：页面已有内容中已包含 `P0_ENTER_SEND_TEST` 字符串，故命中是既有文本，而非本次发送产生。

**结论（已验证事实）：DOM `dispatchEvent(new KeyboardEvent(...))` = 不可靠，不应继续作为实际发送方案（discard）。**
